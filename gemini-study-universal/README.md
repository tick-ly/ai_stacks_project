# Gemini 通用学习 Gem 使用指导（数学书扩写优先）

本目录用于创建一个更通用的学习型 Gemini Gem，适合大学到研究生阶段的知识学习、题目训练、证明分析、复习梳理与文献导读。

这一套更适合：

- 数学书 / 讲义 / 教材连续扩写
- 一组定理、引理、证明的顺序讲解
- 题解、证明补步、习题讲解
- 复习提纲与文献导读

如果你的目标是“代数几何检索问答 + Stacks 引用 + 多源网页证据”，请优先使用 AG 专用目录；当前目录更适合一般学习场景，尤其是数学书扩写。

## 1. 先选入口

当前目录建议分成两种使用方式：

1. 最快落地
- 直接使用 `GEM_最终指令成稿_数学书扩写版.md`
- 适合你已经明确要做“数学书 / 讲义扩写型”Gem，只想把一份稳定成稿直接粘贴进 Gemini 指令框

2. 更通用但不那么聚焦
- 使用 `GEM_最终指令成稿.md`
- 适合你还想保留更宽的学习助手定位，而不是直接锁定“数学书扩写”

一句话建议：

- 要做教材扩写、章节连续讲解、证明补步，优先用“最终成稿_数学书扩写版”
- 要保留更通用的学习助手定位，再用通用成稿

## 2. 最快起步（推荐）

如果你只是想尽快在 Gemini 里得到一个可用版本：

1. 打开 Gemini 的「新 Gem」页面。
2. 名称先填：`数学书与讲义扩写助手`
3. 说明先填：`面向大学到研究生阶段的教材、讲义、定理链条与习题扩写，按闭合批次输出可继续衔接的讲解内容。`
4. 将 `GEM_最终指令成稿_数学书扩写版.md` 里的正文复制到「指令」框。
5. 若可配置工具，建议开启联网检索、URL 读取，以及文件读取能力。
6. 再按下文上传推荐知识文件。

## 3. 文件说明

- `GEM_最终指令成稿_数学书扩写版.md`：当前推荐入口，可直接复制到 Gemini 指令框
- `GEM_最终指令成稿.md`：更通用的学习型版本，适合不想锁定“数学书扩写”的场景
- `knowledge/STUDY_GEM_CORE_PROTOCOL.md`：总流程、batch、continuation、source use 的合并版
- `knowledge/STUDY_GEM_LEARNING_TEMPLATE.md`：知识讲解与题目解析骨架
- `knowledge/STUDY_GEM_EVAL_CHECKLIST.md`：上线前验收清单

## 4. 在 Gemini 中创建 Gem（通用成稿方式）

如果你不想直接用“数学书扩写版”，而想保留更通用的学习助手定位：

1. 打开 Gemini 的“新 Gem”页面。
2. 将 `GEM_最终指令成稿.md` 里的正文复制到「指令」框。
3. 若可配置工具，建议开启联网检索与 URL 读取。
4. 在“知识”区域上传 `knowledge/` 下的推荐文件。

## 5. Knowledge 上传建议

推荐上传顺序：

1. `STUDY_GEM_CORE_PROTOCOL.md`
2. `STUDY_GEM_LEARNING_TEMPLATE.md`

上线前需要再补：

3. `STUDY_GEM_EVAL_CHECKLIST.md`

一句话建议：

- 真正影响回答质量的，是 core + learning template
- eval checklist 更适合验收，不必一开始就塞进 Knowledge

## 6. 快速验收

建议至少用下面 6 类问题做冒烟测试：

1. 低相关
- `帮我想一个周末出游计划。`
- 预期：不强行进入学术讲解。

2. 知识讲解
- `解释一下实分析里一致收敛和逐点收敛的区别。`
- 预期：给定义、例子、反例/误区、用途。

3. 题目解析
- `求证任何有限维线性空间上的两个范数等价。`
- 预期：先说明策略，再逐步证明，不跳大步。

4. 题目提示
- `这道概率题先给我提示，不要直接完整解答。`
- 预期：只给提示或分层提示。

5. 复习梳理
- `把电磁学中高斯定律、散度、通量整理成一页复习提纲。`
- 预期：结构清晰，适合考前复习。

6. 文献导读
- `比较几篇关于 transformer scaling law 的代表性论文，并给阅读顺序。`
- 预期：不是只列标题，而是逐篇分析贡献、方法、局限与关系。

## 7. 常见问题

如果回答太短：

- 检查主指令里是否仍保留“单轮完成一个闭合学习单元”的要求。
- 检查 `STUDY_GEM_LEARNING_TEMPLATE.md` 是否已上传。
- 若是长章节/数学书任务，检查是否同时上传了 `STUDY_GEM_CORE_PROTOCOL.md`。

如果题目解答跳步太大：

- 检查是否保留了“每个关键步骤都说明为什么这样做”的约束。
- 检查是否区分了“提示模式”和“完整解答模式”。

如果文献导读变成书目列表：

- 检查主指令是否保留 `Literature Breakdown / Synthesis / Reading Path`。
- 检查 `STUDY_GEM_CORE_PROTOCOL.md` 是否已上传。

如果出现 `CONTINUE_STATE`、`slots_done` 之类片段：

- 说明 Gem 把内部续写状态直接打印出来了。
- 保留“分阶段续写”，但必须只输出自然语言的 `Next Step`。

如果网页端长任务容易卡成“每轮只吐一点点”：

- 检查主指令是否明确写了“内部微切片，对外闭合批次”。
- 检查 `STUDY_GEM_CORE_PROTOCOL.md` 是否已上传。
- 要求它每轮至少完成一个 theorem/proof/example cluster，或 2-4 个连续编号项。

如果你发现自己真正想要的是“AG 定义 / 判据 / 文献 / Stacks 引用”那类回答：

- 不要硬把当前通用版改成 AG 检索助手
- 直接切到 AG 专用目录，会更稳、更省 prompt 空间
